# Ariadne-artifact-simulator

Ariadne-artifact-simulator contains three main components for generating Ariadne CGRA configurations, running temporal simulations, and parsing test logs:

```text
.dot + .dot.map
       |
       v
BackendCodeEmitter.scala
       |
       v
*_t_arrays_output.txt
       |
       v
wer2.scala -> output.log -> readFile.scala
```

## Requirements

- Java 11 or a compatible version
- SBT 1.x
- Scala 2.13.12
- CMD for the Windows batch script
- Bash for the Ubuntu shell script

All SBT commands use `-mem 12384` to provide enough memory for the simulations.

## Run All Tests

The test scripts run the following tests in order:

1. `ataxno`
2. `gemmno`
3. `k2mmno`
4. `k3mmno`
5. `fftno`
6. `mno`
7. `kmpno`
8. `nwno`
9. `spmvno`

Each test follows this sequence:

1. Run `mycgratemporal.Main`.
2. Overwrite `output.log` with the test output.
3. Run `OutParse.Main` to parse the log.
4. Continue with the next test.

After the complete sequence, `output.log` contains the full per-cycle simulation trace from the final `spmvno` test.

### Windows (Windows 11 recommended)

Double-click the batch file or run it from CMD:

```bat
./run_all_tests_windows.bat
```

### Ubuntu

Make the script executable and run it:

```bash
chmod +x run_all_tests_ubuntu.sh
./run_all_tests_ubuntu.sh
```

If a test process fails, the script still parses its `output.log` before continuing. After all tests finish, the script returns a nonzero exit code if any test or parser process failed.

## `wer2.scala`

Main class:

```text
mycgratemporal.Main
```

`wer2.scala` implements the temporal CGRA simulator. Its main responsibilities are:

- Read the `*_t_arrays_output.txt` configuration generated by CodeEmitter.
- Initialize processing elements, instructions, routes, tags, registers, and memory.
- Execute instructions, data transfers, and memory operations cycle by cycle.
- Compare simulation output with a software reference result.
- Report the completion cycle and any result differences.

### Run One Test

Windows:

```bat
sbt.bat -mem 12384 -batch -no-colors "runMain mycgratemporal.Main ataxno" > output.log 2>&1
```

Ubuntu:

```bash
sbt -mem 12384 -batch -no-colors "runMain mycgratemporal.Main ataxno" > output.log 2>&1
```

Replace `ataxno` with any supported test name.

| Argument | Test function | Default configuration file |
| --- | --- | --- |
| `ataxno` | `ATAXTest` | `benchmark/ataxno.ll_t_arrays_output.txt` |
| `gemmno` | `gemmTest` | `benchmark/gemmno.ll_t_arrays_output.txt` |
| `k2mmno` | `K2MMTest` | `benchmark/k2mmno.ll_t_arrays_output.txt` |
| `k3mmno` | `K3MMTest` | `benchmark/k3mmno.ll_t_arrays_output.txt` |
| `fftno` | `FFTTest` | `benchmark/fftno.ll_t_arrays_output.txt` |
| `mno` | `MERGESORTTest` | `benchmark/mno.ll_t_arrays_output.txt` |
| `kmpno` | `KmpTemporalTest` | `benchmark/kmpno.ll_t_arrays_output.txt` |
| `nwno` | `NWTemporalTest` | `benchmark/nwno.ll_t_arrays_output.txt` |
| `spmvno` | `spmvTest` | `benchmark/spmvno.ll_t_arrays_output.txt` |

When no test name is provided, `ataxno` is used by default.

## `readFile.scala`

Main class:

```text
OutParse.Main
```

`readFile.scala` parses a test log and prints:

- Lines containing `Program finished`, including the completion cycle.
- Lines containing `differ`, indicating result differences.

The parser automatically detects:

- UTF-8
- UTF-16LE, with or without a BOM
- UTF-16BE, with or without a BOM

This allows it to process logs produced by both Windows and Ubuntu output redirection.

Only the first 4 KB is sampled for encoding detection. The log is then processed line by line through a buffered reader, so very large logs are not loaded into memory as one byte array or string.

Windows:

```bat
sbt.bat -mem 12384 -batch -no-colors "runMain OutParse.Main output.log"
```

Ubuntu:

```bash
sbt -mem 12384 -batch -no-colors "runMain OutParse.Main output.log"
```

To parse a different log file:

```bash
sbt -mem 12384 -batch -no-colors "runMain OutParse.Main path/to/test.log"
```

If no path is provided, the parser reads `output.log` from the project directory.

## `BackendCodeEmitter.scala`

Main class:

```text
BackendCodeEmitter.TestMapParse
```

CodeEmitter is responsible for:

- Parsing a data-flow graph from a `.dot` file.
- Parsing placement and routing results from a `.dot.map` file.
- Running backend analysis, routing processing, and configuration verification.
- Generating PE instructions, output routes, redistribution data, tags, and register configuration.
- Writing a `*_t_arrays_output.txt` file that can be consumed by `wer2.scala`.

### Input and Output

For an application path such as `benchmark/ataxno.ll`, CodeEmitter reads:

```text
benchmark/ataxno.ll.dot
benchmark/ataxno.ll.dot.map
```

It generates:

```text
benchmark/ataxno.ll_t_arrays_output.txt
```

### Usage

Windows example:

```bat
sbt.bat -mem 12384 -batch -no-colors "runMain BackendCodeEmitter.TestMapParse benchmark/ataxno.ll 6 16 16 9"
```

Arguments:

| Position | Description | Default |
| --- | --- | --- |
| 1 | Application path without the `.dot` or `.dot.map` suffix | `mNew.ll` |
| 2 | CGRA row and column width | `6` |
| 3 | Number of instructions per PE | `16` |
| 4 | Tag width | `16` |
| 5 | Number of routing bits per output port | `9` |

The entry point reads the fourth argument, but the current `CodeEmit` constructor call still uses the default 16-bit tag width. Keep this argument set to `16` unless the constructor call is updated as well.

`TestMapParse` currently uses the Windows-style base path `.\`. To run CodeEmitter directly on Ubuntu, change `basePath` to `./` or replace it with platform-independent path handling.

The generated file contains these main configuration sections:

- `remuPEInst`: PE instruction encodings.
- `remuPEOut`: D0-D3 output routing.
- `remuPEData`: PE data configuration.
- `remuRedist`: tags and forwarding bit vectors.
- `remuRegV`, `remuRegValid`, and `remuRegTags`: register configuration.
